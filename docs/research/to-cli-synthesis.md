# Сводка исследования: authoring CLI для Дзена

Дата: 2026-11-09. Основание: отчёты [01](01-official-surface.md), [02](02-authenticated-web.md), [03](03-data-crawl-boundary.md), [04](04-actions-failures.md), [05](05-document-model.md). Ни одной мутации в Дзене не выполнено.

## Вывод

Официального API для управления статьями и комментариями нет. RSS и Telegram-бот только пишут, требуют привязанного сайта или публичного Telegram-канала и не умеют читать черновики. Значит, опора продукта это приватный API студии (`editor-api`, `media-api`) и комментариев (`/api/comments/v2`) за типизированным адаптером с дрейф-зондами.

Статья внутри это плоский Draft.js, который почти целиком ложится на CommonMark. Поэтому цель «писать в Дзен как в md» достижима, если Markdown будет видом на документ, а не его хранилищем: `pull` сохраняет нетронутый снимок, `push` отправляет неизменённые блоки байт в байт и заново собирает только правленые.

Сервер, судя по всему, не защищает от перезаписи. Поэтому сверка `base` / `local` / `remote` и журнал мутаций живут на стороне инструмента.

## Поправка к отчётам 02, 04, 05: «Chrome не авторизован» неверно

Пользователь подтвердил, что Дзен в его Chrome авторизован. Воркеры работали не в нём: `ab-chrome` проверяет браузер через `/json/version`, Chrome с отладкой из `chrome://inspect` отвечает на этот путь 404, и скрипт молча уходит в отдельный Chrome for Testing без сессии Дзена. Поэтому в этих отчётах нет авторизованных наблюдений, а утверждение про отсутствие авторизации относится только к тому браузеру.

Прямое CDP-подключение к Chrome пользователя устанавливает TCP-соединение, но команды зависают (проверено дважды, таймаут 30 с). Причина не установлена. Вероятно, Chrome ждёт подтверждения подключения.

## Неизвестное, что снимается авторизованным проходом на чтение

Форма `get-publication` и `/editor-api/v2/user`; значения `state`; список каналов; бандл `article-editor-desktop` с полным перечнем блоков и мутаций; минимальный набор кук; повторяемость авторизованного GET вне браузера; источник `X-FP-Token` и `fp`.

## Неизвестное, что снимается только записью на одноразовом черновике

Формат записи (обёртка), судьба `marker` и неизвестных блоков, `depth > 0`, `STRIKETHROUGH`, имя поля multipart, реакция на устаревший `version`, тело `delete-publication`, значения `delayedPublicationFlagState`. Нужна отдельная явная авторизация с точным сценарием.

## Неизвестное и после этого

Частота автосохранения и поведение при открытой вкладке редактора, пороги капчи и лимиты записи, серверная дедупликация. Для них проектируем консервативно и документируем риск.

## Заполненное дерево решений

Что определилось фактами:

- Транспорт: приватный API, без RSS и без DOM-автоматизации, кроме входа.
- Модель документа: Markdown как вид, снимок `contentState`, выравнивание блоков, якоря `dzen:raw`, неизвестное падает, а не деградирует (05 §5, §6).
- Безопасность мутаций: отправка один раз, журнал до отправки, граница отправки, ограниченная сверка, исходы `confirmed` / `accepted_pending` / `rejected` / `outcome_unknown`, dry-run без сети и авторизации, `publish` отдельно от `push` (04).
- Архив: crawlkit; локальные запросы без сети; рабочие копии вне SQLite; схема v2 с raw и ревизиями (03).
- Сначала чинятся дефекты D1–D4 текущего краулера (03 §1.2).

Что решил пользователь (2026-11-09):

1. Один бинарник `dzen`, краулер переезжает в `dzen crawl`. Запрет записи для crawl обеспечивается типами и тестом.
2. Файлы и `pull` / `push` / `diff` / `status`, без точечных команд правки тела.
3. CLI умеет всё, у него есть `--dry-run` и подтверждения. Границы автономии задаёт скилл `skills/dzen`.
4. 2Captcha встроен и работает автоматически, без запроса пользователю. Позиция README про капчу снимается.
5. Импорт уже авторизованной сессии из Chrome главный путь, отдельное окно `auth login` запасной. Пользователя не беспокоить.
6. Мультиаккаунт: один профиль на аккаунт и канал.
7. Живые проверки, включая публикацию, разрешены на пустом тестовом канале. Чужие материалы и пользователи вне области.
8. Объём: публикации, их создание, редактирование и настройки, картинки, комментарии, бан. Статистика, закрепление, подборки, премиум, промо отложены.

Итоговый контракт: [`docs/CLI_SPEC.md`](../CLI_SPEC.md). Живые контракты записи: [отчёт 06](06-live-authenticated.md). Важная поправка из него: `delayedPublicationFlagState:"off"` с публикацией выпускает запланированную статью немедленно (захват lifecycle), поэтому «снять план» можно только удалением.
